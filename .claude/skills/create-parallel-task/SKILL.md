# Задача для параллельного агента

Задача — файл `tasks/NN-<ID>-<Slug>.md` в корне репозитория (каталог в `.gitignore`). Её возьмёт
агент в отдельном worktree: он не видит ни этого разговора, ни других задач, и запушит результат
в `origin/master`, куда одновременно пушат агенты других задач. Отсюда два требования: задача
самодостаточна, и её файлы не пересекаются с файлами других открытых задач. Flow агента описан в
`CLAUDE.md`, раздел «Задачи и параллельная работа», — задача пишется под него.

Запрос: $ARGUMENTS

## 1. Актуальный код

Корень — `git rev-parse --show-toplevel`. Сделай `git fetch origin`; если `master` отстаёт
(`git rev-list --count master..origin/master` больше нуля) — `git pull --ff-only`, иначе ссылки
на строки разойдутся с тем, что увидит агент. Не получилось (локальные правки, расхождение) —
скажи пользователю и ссылайся на `origin/master` (`git show origin/master:<path>`).

Изучи код по теме: точные `путь:строки`, имена функций, существующие тесты рядом, что говорит
`README.md` и `CLAUDE.md` об этом месте. Задача по памяти — задача с неверными ссылками.

## 2. Открытые задачи и пересечения

Закрытые задачи видны по трейлерам в `origin/master`:

```sh
git log origin/master --format=%b | grep -o '^Task: .*' | sort -u
```

Открытые — файлы в `tasks/`, чьё имя без `.md` там не встречается. Из каждой открытой возьми
строку `**Файлы:**` (у задач, написанных до этого скилла, её нет — оцени по тексту) и сравни со
списком новой задачи. Пересечение — не запрет, а решение, которое
принимается явно:

- тот же файл, разные места (две новые подкоманды в `cmd/aish/main.go`, две строки в таблице
  пакетов) — допустимо, но в новой задаче укажи точное место правки;
- та же функция или та же логика — объедини задачи, или поставь `**Зависит от:** NN` (вторая
  пойдёт после того, как первая окажется в `origin/master`), или перережь границы;
- задача переписывает `init.bash`, `proxy.go`, рефакторит пакет целиком — `**Параллельно:** нет`,
  пользователь запустит её одну.

Если пересечение требует выбора между вариантами — спроси пользователя до записи файла; если
решение очевидно — прими его и назови в итоге.

## 3. Размер и границы

Одна задача — один коммит одного агента: 1–3 пакета, дифф в пределах нескольких сотен строк.
Больше — дели, причём по файлам, а не по этапам, чтобы части шли параллельно. Если части
взаимодействуют, зафиксируй интерфейс (сигнатуру, имя rpc-метода, формат маркера, ключ конфига)
в обеих задачах — тогда их можно делать одновременно, не дожидаясь друг друга.

Предпочитай решения, которые ложатся в новые файлы: новый `cmd/aish/<cmd>.go` вместо ста строк в
`main.go`, новый `<topic>_test.go` вместо дописывания в существующий. Горячие файлы (`main.go`,
`proxy.go`, `rpc.go`, `config.go`, `builtin.go`, шапка `init.bash`, `README.md`, `CLAUDE.md`)
правят все задачи сразу — для них в задаче стоит точное место и объём («одна строка в таблицу
пакетов после `internal/mcp`», «абзац после …»), а не «обнови документацию».

## 4. Файл задачи

- `NN` — следующий после максимального в `tasks/`, две цифры.
- `ID` — пункт плана: `2.N` для багов и небольших улучшений (следующий `N` после максимального
  в `tasks/`), `1X` — этапы рефакторинга, их называет пользователь.
- `Slug` — по-английски, через дефис, 2–5 слов.

Шаблон; разделы в этом порядке, пустой раздел не выдумывай, а пропусти:

```markdown
# <Что не так или что появится — одной строкой>

**Приоритет:** высокий | средний | низкий — и почему, в двух словах.
**Файлы:** `path/a.go` (функция `X`), `path/b_test.go` (новый), `README.md` (раздел «…»).
**Зависит от:** NN-ID-Slug | —
**Параллельно:** да | нет — почему.

## Проблема

Что происходит и почему это плохо, с `путь:строки`. Как воспроизвести, если есть как.

## Предложение

Как сделать — достаточно конкретно, чтобы агент не выбирал архитектуру сам: какие функции,
сигнатуры, что с краевыми случаями. Отвергнутые варианты и почему — по строке на каждый.

## Границы

Чего не делать: соседние проблемы, которые заметны, но не входят в задачу; рефакторинги, которых
не надо; общие файлы, которые трогать только в названном месте.

## Документация

`README.md` — какой раздел и что в нём меняется; `CLAUDE.md` — какой пункт «Что легко сломать»
или строка таблицы; шапка `init.bash` — если маркеры. Или «не требуется».

## Критерий готовности

Проверяемые утверждения: какие тесты появятся и что проверяют; как убедиться руками.
```

## 5. Напоследок

Перечитай файл глазами агента, который видит только репозиторий и его: всё ли названо, чтобы не
гадать и не ходить в чужие файлы? Пользователю покажи путь к файлу, строку `**Файлы:**` и
найденные пересечения с открытыми задачами.
