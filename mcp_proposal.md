# Задача: добавить в aish поддержку MCP

## Цель

Инструменты MCP-серверов должны стать обычными командами shell — такими же, как
встроенные `read_file`/`edit_file` и внешние инструменты из `~/.config/aish/tools/`.
Одна реализация обслуживает и человека, который набирает команду, и агента.

## Принцип

У aish инструмент — это команда. `makeRunDir` (`internal/proxy/proxy.go:173`) уже
генерит в `$AISH_RUN/bin/` обёртки `#!/bin/sh exec aish tool NAME "$@"`. MCP ложится
в ту же форму: получили `tools/list` — положили обёртки в `bin/`.

## Архитектура

Процессом MCP-сервера владеет **прокси**: он живёт столько же, сколько shell, и уже
держит unix-сокет (`internal/rpc`). Добавь на сокет два метода: `mcp_list` и `mcp_call`.

```
github_search "query"           человек набрал
  → aish tool github_search …   обёртка из $AISH_RUN/bin
      → rpc mcp_call            → прокси → stdio JSON-RPC → сервер
агент вызвал github_search      → Tool.Run (closure) → тот же rpc mcp_call
```

MCP-инструмент — это `tools.Tool` с непустым `Run`, где `Run` делает один RPC к прокси.
`agent.call` (`internal/agent/agent.go:231`) уже трактует `Run != nil` как «живого
вывода нет, покажи однострочный итог, длинное — в Ctrl+O»: это ровно поведение, нужное
MCP. `agent.go`, folding и политики менять не нужно.

Серверы поднимать **лениво**, при первом обращении: иначе запуск терминала встанет на
несколько секунд из-за npx.

## Решения, которые надо соблюсти

1. **По умолчанию MCP-инструменты НЕ попадают в `req.Tools`** (`internal/agent/agent.go:152`).
   Пять серверов по двадцать инструментов — это сотня JSON-схем в каждом запросе.
   Вместо этого они доступны как команды, а в системный промпт добавляется одна строка:
   «Дополнительные инструменты доступны как команды: `aish tool` — список,
   `aish tool NAME -h` — справка». Переключатель `expose = "tools"` в конфиге сервера
   отдаёт схемы модели нативно.

2. **Имена:** `<сервер>_<инструмент>`, например `github_search` — подходит под
   `^[a-zA-Z0-9_-]{1,64}$` у Anthropic и под стиль `read_file`.

3. **Не создавать обёртку, перекрывающую существующую команду в `PATH`.**
   `internal/shellinit/init.bash:21` делает `PATH="$AISH_TOOLS_PATH:$PATH"`, поэтому
   инструмент с именем `ls` молча подменит coreutils для всего shell. Имена приходят
   извне — проверяй через `exec.LookPath` и пропускай с предупреждением.

4. **Схема → CLI.** Обязательные скалярные свойства — позиционные, в порядке из сырого
   JSON (`json.RawMessage`, а не `map[string]any`: map теряет порядок, и usage будет
   меняться между запусками). Необязательные — `--flag value`, булевы — `--flag`.
   Объекты и массивы — `--prop '<json>'`, своего синтаксиса не изобретать.
   Одна функция должна и разбирать аргументы, и печатать usage.

5. **Вывод:** блоки `text` — в stdout; `image`/`blob` — во временный файл, в stdout путь;
   `isError: true` — **ненулевой exit**, чтобы `$?` и `&&` работали для человека.

6. **Политика:** добавь в `policy.Input` (`internal/policy/policy.go:27`) поле `server`.
   Остальной Rego-слой покрывает MCP бесплатно — проверка идёт по `tool` + `args` до вызова.

7. **Конфиг — отдельный файл `~/.config/aish/mcp.yaml`** (путь переопределяется полем
   `mcp_config` в `config.toml`). `config.toml` остаётся как есть: список серверов
   вложеннее остальных настроек, и YAML для него читается лучше.

```yaml
servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_TOKEN: $GH_TOKEN
    expose: commands   # по умолчанию; tools — отдавать схемы модели
  sentry:
    url: https://mcp.sentry.dev/sse
```

   Парсер брать `go.yaml.in/yaml/v3` — он уже в графе модуля как indirect (тянет OPA),
   новой зависимости не появится, надо лишь повысить до прямой. Отсутствующий файл —
   не ошибка, просто нет серверов. `$VAR` в `env` раскрывать через `os.ExpandEnv`,
   чтобы токены не лежали в конфиге открытым текстом.

## Чего не делать

Не тащить MCP целиком: `resources` — максимум команда `mcp_read URI`, а `prompts`,
`sampling` и `roots` пропустить. SDK не нужен, stdio JSON-RPC клиент пишется руками.
Ориентир по объёму — около 400 строк на всё; проект целиком 4.5k, держись этого масштаба.
Сломанный или недоступный сервер не должен мешать работе shell: таймаут, внятная ошибка,
ненулевой exit.

## Проверка

`go vet ./...` и `go test ./...` должны проходить. Напиши тест со стаб-сервером
(маленький процесс, отвечающий на `initialize`/`tools/list`/`tools/call` по stdio) —
без сети и без npx. Отдельно покрой тестами схема→CLI и отказ от перекрытия команд PATH.
