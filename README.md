# aish — LLM внутри твоего bash

aish запускает твой обычный bash — с `~/.bashrc`, алиасами, промптом и историей — и подсаживает
в него ассистента. Набираешь команду — её исполняет bash. Пишешь фразу с заглавной буквы — отвечает
модель, которая видит всё, что происходило в терминале: команды, их вывод и прошлый разговор.

```
$ make
main.go:12: undefined: foo
? Почему не собирается?
⚙ read_file main.go
❯ grep -rn "func foo" .  (1 line · ctrl+o to expand)
В main.go вызывается foo(), но функция нигде не объявлена…
```

Ассистент работает в том же shell, что и ты: его `cd`, `export` и объявленные функции остаются
после того, как он закончил. Никаких подпроцессов и песочниц — он отдаёт команды твоему живому bash.

## Установка

```sh
go build -o ~/.local/bin/aish ./cmd/aish
export AISH_API_KEY=...        # или ANTHROPIC_API_KEY / OPENAI_API_KEY
aish                           # новая сессия
aish --resume                  # продолжить последнюю
aish resume                    # выбрать сессию из списка
```

Чтобы aish открывался в каждом новом терминале, сделай его командой терминала или допиши в конец
`~/.bashrc`:

```sh
[[ -z $AISH_SOCK && $- == *i* ]] && exec aish
```

## Команда или вопрос?

Строку, первое слово которой — команда, алиас или функция, выполняет bash, как бы она ни выглядела:
`git status`, `Rscript x.R`. Остальное уходит модели, если похоже на вопрос:

- начинается с заглавной буквы: `Как найти большие файлы?`, `Find big files` (`find` — команда,
  `Find` — нет);
- кончается на `?`: `ls?` (такой команды нет; а `ls foo?` выполнит bash — `ls` команда, `foo?` —
  шаблон имён файлов);
- это слова, а не shell: два слова и больше и ни одного из `` |&;<>()$`\= `` — `why does this fail`,
  `почему не собирается`.

Одно слово (`gti`) и строка с синтаксисом shell (`gti status | head`) достаются bash с его обычным
`command not found`. Цена третьего правила — опечатка из двух слов: `gti status` уйдёт модели, но
та видит контекст shell и ответит «ты имел в виду `git status`?». Для заглавных букв кириллицы
нужна UTF-8-локаль.

Правила настраиваются таблицей `[route]` в `config.toml`, здесь — значения по умолчанию:

```toml
[route]
capital = true    # строка с заглавной буквы
not_found = true  # слова, а не shell: то, на что bash ответил бы command not found
suffix = "?"      # строка, которая кончается на suffix; "" — правило выключено
min_words = 2     # сколько слов нужно для not_found
```

С `not_found = false` такие строки достаются bash, а после первого `command not found` за сессию
aish подскажет префикс `?`. Свой `command_not_found_handle` (pkgfile, command-not-found) работает
как прежде для всего, что досталось bash. `[route]` читается при старте aish: после правки
перезапусти его.

Когда правила мешают, есть префиксы:

- `?текст` — точно модели: `?почему не собирается`;
- `@файл …` — тоже модели, файл прикладывается к запросу (см. ниже);
- `/скилл …` — тоже модели, с инструкцией скилла; имя скилла первым словом (`fix-issue 123`)
  работает так же (см. «Скиллы»);
- `!команда` — точно bash; `!!`, `!$`, `!-2` и прочие history expansion работают как раньше.

В историю попадает то, что ты набрал, вместе с префиксом. На экране строка с вопросом отличается от
команд: `$` (или `#`) в конце промпта заменяется на `?`.

## Что умеет ассистент

Модель работает сама, без подтверждения каждого шага; ограничить её можно политиками (ниже).
Инструменты:

| инструмент | что делает |
|---|---|
| `bash` | команда в **твоём живом shell**: `cd`, `export`, функции сохраняются; вывод свёрнут |
| `read_file PATH [OFFSET] [LIMIT]` | читает файл с номерами строк |
| `write_file PATH [CONTENT\|-]` | пишет файл (содержимое аргументом или со stdin) |
| `edit_file PATH OLD NEW [REPLACE_ALL]` | точечная замена в файле |
| `ask_user` | спрашивает тебя, когда задача неоднозначна: до четырёх вопросов с вариантами, по одному на экране. `↑↓` или цифра — выбор, пробел — отметка, если можно несколько, «Other» — свой ответ, Enter — дальше, `←`/Backspace — назад, Esc — отмена. Остаётся сводка `заголовок: ответ`. Только для модели, командой не набирается |
| свои | исполняемые файлы из `~/.config/aish/tools/` |
| скиллы | `SKILL.md` из `~/.claude/skills/` и `.claude/skills/` |
| MCP | инструменты серверов из `~/.config/aish/mcp.yaml` |

Все инструменты — ещё и команды shell: `read_file main.go 1 20` можно набрать самому, `aish tool`
покажет полный список.

`Ctrl+C` прерывает и ответ, и команду, которую запустил ассистент; модель узнает, что её прервали.

### Файлы в запросе

Чтобы модель сразу получила файл, упомяни его через `@`: `Изучи заметки @*.md и скажи, что делать`.
Под запросом появится строка на каждый найденный файл — `@todo.md (12 lines)` — и модели не придётся
тратить ход на `read_file`.

- `@путь` — файл или папка (для папки — список файлов); `~` раскрывается, относительные пути — от
  текущего каталога;
- `@шаблон` — glob с `*`, `?`, `[…]` и `**` (`@src/**/*.go`); скрытые файлы, `.git` и `node_modules`
  берутся, только если названы явно;
- путь с пробелами — в кавычках: `@"мои заметки.md"`; знак препинания после упоминания к пути не
  относится, `user@host` упоминанием не считается;
- бинарные файлы пропускаются; лимиты — 40 KB на файл, 200 KB и 50 файлов на запрос, остальное
  модель дочитает сама;
- ненайденный файл отмечается под запросом: `@x.md: no such file`.

## Экран

**Ответы** рендерятся как markdown по ходу генерации: заголовки, списки, цитаты, ссылки как
`текст (url)`, таблицы в рамке (появляются целиком, когда дописаны), подсветка кода по языку
(стиль — `code_style`). Пока модель думает, крутится спиннер `⠋ thinking…`.

**Вывод команд ассистента** свёрнут: на экране только команда и статус у правого края её последней
строки — `(30 lines · exit 1 · ctrl+o to expand)`; счётчик строк обновляется, пока команда работает.
Так же выглядят вызовы других инструментов: `⚙ read_file …` — одна строка, обрезанная по ширине
терминала с `…`, статус у её правого края; однострочный результат (`wrote 4326 bytes to …`) идёт
строкой ниже. Если подсказка про Ctrl+O не влезает, статус короче — `(30 lines · exit 1)`, а в узком
терминале он уходит строкой ниже.
Команда длиннее трёх строк показывается первыми тремя и строкой `… (+N lines)`; целиком она видна
в Ctrl+O.
`fold_lines = N` показывает первые N строк, `-1` отключает сворачивание.

**Ctrl+O** открывает полноэкранный просмотр всего, что было свёрнуто за текущий или последний
запрос: вывод команд, результаты `read_file`, даже ещё работающую команду. Листать — `↑↓`/`j k`,
`PgUp PgDn`/пробел `b`, `g G`; закрыть — Ctrl+O, `q` или Esc. Работает в любой момент, в том числе
пока модель пишет. Если сворачивать было нечего, Ctrl+O достаётся readline или запущенной программе.
`aish expand` печатает свёрнутое прямо в терминал.

**Статус справа от промпта** — занятый контекст и модель: `34k/1.0M 3% · claude-opus-5`. Жёлтый от
70%, красный от 90%: пора сделать `aish compact` или `clear`. Строку рисует aish, а не `PS1`, так что
она уживается с любым промптом (starship и т. п.); в узком терминале не показывается, выключается
через `prompt_status = false`.

**`clear`, `reset` и Ctrl+L** сбрасывают контекст: модель видит только то, что осталось на экране.
Сессия при этом та же — ID, имя и журнал не меняются, `aish session show` покажет и то, что было до
очистки. Очистка внутри vim, less и других полноэкранных программ не считается.

## Контекст и модель

- `aish status` — сколько контекста занято и как это посчитано (точное число токенов из последнего
  ответа модели плюс оценка всего, что появилось после), сколько команд и запросов с последнего
  compact, сколько токенов потрачено за сессию и сколько входных прочитано из кэша провайдера,
  профиль, провайдер, модель, её окно и effort, настройки и пути.
- `aish compact [о чём помнить]` просит модель кратко изложить сессию: запросы, что сделано, пути,
  ошибки, текущее состояние. Дальше модель получает только эту сводку и то, что было после неё.
  Журнал не стирается — `aish session show` покажет всё.
- Когда контекст переваливает за `compact_at` окна (по умолчанию 0.8), aish сам делает то же, что
  `aish compact`, перед следующим ходом модели — `compacted: 28k → 3.1k tokens` — и запрос идёт
  дальше со сводки: инструкции (CLAUDE.md) перечитываются, а запрос, на который модель ещё не
  ответила, уходит после сводки как набран. Если порог перейдён, пока ты работаешь в shell, статус
  справа от промпта помечает это `compact?`, а сводку делает следующий запрос — ход модели ради неё
  не тратится. Вторую сводку сразу за первой aish не делает: если порог всё ещё превышен из-за
  огромного результата последней команды, модель получает его урезанным (в журнале он целиком).
  Нужен известный размер окна — от API или `context_window`; `compact_at = 0` выключает.
- `aish model` — список моделей, которые отдаёт API, с размером окна; текущая отмечена `*`.
  `aish model ИМЯ` переключает модель **для этого shell**; насовсем — `model` в `config.toml`.
  Переключает только пользователь: `aish model` из команды ассистента получает отказ, как и
  `aish resume` и `aish clear`.
- Effort — насколько долго модель думает. `aish model high` меняет только его, `aish model
  claude-sonnet-5 xhigh` — модель вместе с effort, `aish model default` возвращает уровень, который
  модель выбирает сама. Уровни Anthropic: `low`, `medium`, `high`, `xhigh`, `max`; у OpenAI ещё
  `none` и `minimal`. Насовсем — `effort` в `config.toml` или `$AISH_EFFORT`. Если API не сообщает,
  какие уровни знает модель (так у cliproxyapi), неподходящий отвергнется на первом запросе. На
  `xhigh` и `max` лимит ответа поднимается с 32000 до 64000 токенов, если `max_tokens` не задан.
- Профиль (`[profiles.ИМЯ]` в `config.toml`, см. «Настройки») — другой endpoint целиком: провайдер,
  `base_url`, ключ, модель, effort. `aish model local` переключает shell на профиль `local` с его
  моделью и effort, `aish model local qwen3:8b` и `aish model local qwen3:8b high` — на другую
  модель и effort этого профиля. Первое слово сначала ищется среди профилей, потом среди моделей и
  уровней effort: модель с именем профиля дают вторым словом, после профиля. `aish model` без
  аргументов показывает и профили (текущий отмечен `*`), и модели текущего. Профиль, как модель и
  effort, — на этот shell, хранится в `<id>.state` и возвращается с `aish resume`. Статус справа от
  промпта называет профиль, если он не тот, что выбирает `config.toml`. Насовсем — `profile` в
  `config.toml` или `$AISH_PROFILE`.

Внутри aish эти команды работают и без префикса: `status`, `model claude-sonnet-5 xhigh`, `compact`,
`session show`, `resume ИМЯ`, `mcp`, `skills`. Это обёртки в `$AISH_RUN/bin`, как у инструментов, и
правило то же: имя, занятое командой в `PATH`, обёртки не получает — так `expand` остаётся
coreutils, а свёрнутое показывают `aish expand` и Ctrl+O. Функция или алиас из `~/.bashrc` с таким
именем имеет приоритет. Инструмент или скилл с именем `status`, `model` и т. п. командой не станет —
только `aish tool ИМЯ`.

## Сессии

Сессия — это журнал (команды, вывод, запросы, ответы) **плюс состояние shell**. По умолчанию сессия
живёт только в памяти aish и с выходом пропадает; на диск её кладут `aish clear save` и `aish new`,
и дальше она пишется насквозь. Сессии глобальные: любую можно продолжить из любого терминала, но
одну сессию держит только один aish.

- `aish --resume` продолжает самую свежую сессию, которую никто не держит.
- `aish resume` открывает список: имя или ID, когда использовалась, каталог, число запросов,
  последний запрос. `↑↓`/`j k`, `PgUp PgDn`, `g G` — двигаться, Enter — продолжить, `r` —
  переименовать, `d` и `y` — удалить, `q`/Esc — выйти. `[this shell]` — сессия этого shell,
  `[open]` — занята другим aish.
- `aish resume ID|ИМЯ` — сразу, без списка; хватит однозначного начала ID или имени.
- Вне aish `aish resume` запускает aish с этой сессией. Внутри — переключает текущий shell: со
  следующего приглашения журнал и состояние уже той сессии, а изменения прежней откатываются.
  Переключаться может только пользователь, не ассистент. Несохранённая сессия, из которой
  переключились, теряется — `aish resume` об этом предупреждает.
- `aish clear` начинает новую несохранённую сессию; прежняя, если не сохранена, пропадает.
- `aish clear save [ИМЯ]` сохраняет текущую — журнал, состояние shell, имя — и начинает новую.
- `aish new [ИМЯ]` начинает новую сессию, которая сохраняется с первой записи; несохранённая
  прежняя пропадает. Имя — всё после команды, без кавычек: `aish new разбор логов`.
- `aish session rm ID|ИМЯ…` удаляет сохранённые сессии с диска — как и `aish resume`, по ID, имени
  или их однозначному началу. Сессию этого shell удалить нельзя (сначала `aish clear`), открытую в
  другом aish — тоже.
- `aish session prune --older 30d` удаляет сессии, которыми не пользовались 30 дней (`12h` — 12
  часов, `0d` — все); открытые остаются. Без `--older` берётся `sessions_ttl` из настроек: если он
  задан (`sessions_ttl = "30d"`), aish и сам удаляет такие сессии при каждом запуске. По умолчанию
  `"0"` — сессии хранятся, пока их не удалят.

Восстанавливается всё, чем shell отличается от свежезапущенного (после `~/.bashrc`): переменные
(в том числе неэкспортированные и массивы), функции, алиасы, `set -o`/`shopt`, текущий каталог,
а также модель и effort из `aish model`. Остальное окружение — `DISPLAY`, `SSH_AUTH_SOCK` и т. п. —
берётся из нового терминала, а не застревает из прошлого. Не восстанавливаются история команд
(у неё свой `HISTFILE`), `trap`, фоновые задачи, стек `pushd`, `readonly`-переменные, имена с `_`
в начале и переменные самого bash. Состояние снимается на каждом приглашении встроенными командами
bash, без fork.

Файлы сохранённых сессий лежат в `~/.local/share/aish/sessions/`: `<id>.jsonl` — журнал,
`<id>.state` — состояние shell (значения переменных открытым текстом; права 0600), `<id>.name` —
имя, `<id>.lock` — пока сессия открыта. `aish session show` печатает журнал.

Что не пишется на диск, задают два списка шаблонов в настройках (синтаксис — как у `HISTIGNORE`):

- `journal_ignore` — команды, чей вывод не попадает в журнал, а значит и к модели: по умолчанию
  `env`, `printenv`, `history`, `cat *credentials*` и всё с `secret`. Шаблон сверяется с каждой
  простой командой строки целиком, так что `sudo env` и `env | grep X` тоже подходят; в журнале
  остаётся сама команда с выводом `[not recorded]`.
- `state_ignore` — переменные, которые не попадают в `<id>.state` и не восстанавливаются: по
  умолчанию `*TOKEN*`, `*SECRET*`, `*KEY*`, `*PASSWORD*`, `AWS_*`.

Пустой список (`journal_ignore = []`) отключает фильтр. Это защита от случайного попадания в
журнал, не маскирование: `cat secret.txt | base64` отфильтруется, а `grep -r token .` — нет.

Секреты в том, что уходит модели, маскируются: вывод команд, файлы из `@`, инструкции и результаты
инструментов проходят через набор регулярок (ключи AWS, GitHub, OpenAI, Slack, блоки `PRIVATE KEY`,
`password=`/`token:`/`api_key=` и т. п.), от значения остаются первые четыре символа — `AKIA***`.
Сам запрос пользователя не трогается, журнал и экран тоже: `aish session show` показывает то, что
видел пользователь. Свои регулярки — `mask` в `config.toml` (группа в скобках прячет только её,
остальное — ориентир для модели), встроенные выключает `mask_defaults = false`; `aish status`
показывает, сколько их.

## Инструкции (CLAUDE.md)

Как в Claude Code, модель получает инструкции из файлов: глобальные `~/.claude/CLAUDE.md` и
`~/.config/aish/CLAUDE.md`, и по папкам — `CLAUDE.md`, `.claude/CLAUDE.md`, `AGENTS.md`,
`CLAUDE.local.md` в каждой папке от `/` до текущей. Файл читается при первом запросе из папки
(под запросом появляется его путь), попадает в сессию один раз и перечитывается, если изменился.
После `clear` и `aish compact` инструкции загружаются заново.

## Свои инструменты

Инструмент — любой исполняемый файл в `~/.config/aish/tools/` с шапкой
(пример — `examples/tools/weather`):

```sh
#!/bin/sh
# aish:desc Show the weather forecast for a city
# aish:arg city string City name
# aish:arg days? integer Optional argument
# aish:arg body stdin Passed on standard input
```

Вызывается он так же, как набирают `aish tool NAME`: обязательные аргументы — позиционно, в порядке
шапки; необязательные (`name?`) — флагами `--name значение` (булев — просто `--name`);
`stdin`-аргумент приходит на стандартный ввод; объекты и массивы — JSON. Каждый переданный аргумент
есть и в `$AISH_ARG_<NAME>`, так что необязательные проще читать оттуда: `${AISH_ARG_DAYS:-1}`.
`aish tool NAME -h` показывает форму вызова, для этой шапки — `weather CITY [--days DAYS] BODY|-`.

## Скиллы

Скиллы Claude Code работают без изменений: каталог с `SKILL.md` (YAML-фронтматтер с `description`,
дальше инструкция) и файлами, на которые она ссылается. Имя — `name` из фронтматтера или имя каталога.
Ищутся в `~/.claude/skills/`, `~/.config/aish/skills/` и `.claude/skills/` каждой папки от `/` до
текущей; одноимённый скилл ближе к текущей папке перекрывает дальний (в Claude Code наоборот).

```
$ aish skills
fix-issue [issue-number]  ~/.claude  [not for the model] Fix a GitHub issue
pdf-processing            ~/.claude  Extract text and tables from PDF files…
release-notes             ./.claude  Draft release notes from the git log…
$ fix-issue 123                      # модель получает инструкцию с подставленным 123 и выполняет её
$ Сделай релиз /release-notes v2.1   # то же, упоминанием в любом месте запроса
$ aish tool release-notes v2.1       # просто напечатать инструкцию
```

- Скилл — обычный инструмент: модель видит имя и описание и вызывает его сама, когда задача
  подходит. Инструкция попадает в контекст только при вызове — вместе с путём к каталогу и списком
  его файлов, чтобы модель открыла `reference.md` или запустила `scripts/*`. `${CLAUDE_SKILL_DIR}`
  заменяется на путь каталога.
- Аргументы — как в Claude Code: в shell это слова после имени команды (`fix-issue 123 "with
  tests"`). `$ARGUMENTS` — вся строка, `$N` и `$ARGUMENTS[N]` — N-е слово с нуля, `$name` — слово с
  позицией `name` в списке `arguments` фронтматтера; `\$1` — буквальный `$1`. Если ни одна
  подстановка аргументы не взяла, они дописываются в конец строкой `ARGUMENTS: …`. `argument-hint`
  показывается в `aish skills` и в описании для модели. При упоминании внутри фразы (`Сделай релиз
  /release-notes v2.1`) `$ARGUMENTS` — вся фраза без `/имя`: `Сделай релиз v2.1`.
- `disable-model-invocation: true` прячет скилл от модели — остаётся вызов пользователем: `deploy
  prod` или `/deploy prod` отдаёт инструкцию модели, сама она его не позовёт. Удобно для действий
  вроде деплоя.
- Скилл набирается как команда (`fix-issue 123`) или упоминается как `/имя` в любом месте запроса.
  Инструкция с подставленными аргументами прикладывается к запросу, как файл по `@`, — под запросом
  строка `/fix-issue (~/.claude/skills/fix-issue/SKILL.md)`; аргументы — слова запроса без самого
  упоминания. Имя, занятое командой, функцией или алиасом, исполняет bash, а скилл остаётся
  доступен как `/имя`. Проектные скиллы видны сразу, перезапуск не нужен.
- `allowed-tools` передаётся модели как подсказка; остальные поля фронтматтера не используются.
- `aish skills` показывает скиллы и проблемы с ними: битый фронтматтер, нет `description`, имя с
  недопустимыми символами (можно буквы, цифры, `-` и `_`), `name` не совпадает с каталогом, имя
  занято инструментом или командой в `PATH`.

## MCP-серверы

Инструменты MCP-серверов становятся командами shell вида `<сервер>_<инструмент>`:
`github_search_issues "bug" --state open`. Их набирает и пользователь, и модель через `bash`.
Серверы описываются в `~/.config/aish/mcp.yaml` (путь меняется `mcp_config` в `config.toml`;
нет файла — MCP выключен):

```yaml
servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_TOKEN: ${GITHUB_TOKEN}   # переменные раскрываются
    timeout: 120                      # секунд на вызов, по умолчанию 60
  remote:
    url: https://example.com/mcp      # Streamable HTTP
    headers:
      Authorization: Bearer ${TOKEN}
    expose: tools                     # отдавать модели схемы как обычные инструменты
```

- Сервер запускается при первом вызове и живёт до выхода из shell. Список инструментов кэшируется в
  `~/.cache/aish/mcp/`, поэтому в следующий раз команды появятся сразу. Сервер, которого нет в кэше,
  опрашивается в фоне при старте; модель увидит его инструменты со следующего запроса, `aish tool`
  дождётся старта.
- Аргументы — как у своих инструментов: обязательные строки и числа позиционно, остальное флагами
  `--name значение`, булевы — `--name`, объекты и массивы — JSON. `NAME -h` показывает форму.
- Текст идёт в stdout, картинки и бинарные данные — во временный файл, печатается его путь. Ошибка
  инструмента или упавший сервер — ненулевой код возврата и сообщение с концом stderr сервера.
- Если команда с таким именем уже есть в `PATH`, обёртка не создаётся; причина видна в `aish tool`.
- По умолчанию модель не получает схемы MCP-инструментов — только строку про `aish tool` в системном
  промпте — и находит их сама. `expose: tools` отдаёт схемы как обычным инструментам.
- `aish mcp` показывает состояние каждого сервера, транспорт, команду или URL (секреты скрыты),
  инструменты и, для упавших, ошибку.
- Поддерживаются только инструменты (без resources, prompts, sampling), транспорты — stdio и
  Streamable HTTP; старый HTTP+SSE не поддерживается.

## Политики

Чтобы запретить `sudo` или спрашивать перед установкой пакетов, язык политик не нужен — хватит
`[policy]` в `config.toml`:

```toml
[policy]
deny = ["sudo *", "rm -rf /", "git push --force*", "git push -f*"]
ask  = ["apt install *", "pacman -S *", "git push*"]
write_outside_home = "deny"      # "allow" | "ask" | "deny"; нет — allow
```

Шаблон сравнивается с каждой простой командой bash-строки — с её argv через пробел, в том числе
внутри конвейеров, `$(...)`, `bash -c '...'` и за `sudo`; строка, которую не удалось разобрать,
сравнивается целиком. `*` ловит всё, **включая пробелы и `/`**, `?` — один символ, других
спецсимволов нет: `sudo *` ловит `sudo cat /etc/x`, а `rm -rf /` не ловит `rm -rf /tmp/x`.
`deny` запрещает, `ask` спрашивает `[y/N]`, `write_outside_home` решает за `write_file` и
`edit_file` с путём вне `$HOME`. Что правила не назвали — разрешено. Правила и Cedar проверяются
оба, побеждает строгий: deny любого — deny, затем ask. `[policy]` в `.aish.toml` проекта
добавляется к глобальному — проект может только ужесточить. `aish policy` показывает и число
правил.

Каждый вызов инструмента проверяется политиками на [Cedar](https://docs.cedarpolicy.com/) из
`~/.config/aish/policy/*.cedar`. `forbid` возвращается модели с причиной, `forbid` с аннотацией
`@ask("…")` спрашивает тебя `[y/N]`; `@reason("…")` — текст, который увидят модель и ты. Нет
политик — разрешено всё.

Что видит политика (principal везде — `Model::"<имя модели>"`):

| инструмент | action | resource | context |
|---|---|---|---|
| `bash`, на каждую простую команду | `Action::"run"` | `Command::"rm"` (basename) | `program`, `args`, `flags` (`-rf` → `r`, `f`; `--force` → `force`), `operands`, `paths`, `text`, `line`, `cwd`, `home`, `parse_error` |
| `read_file` / `write_file`, `edit_file` | `Action::"read"` / `Action::"write"` | `File::"/abs/path"` | `path`, `exists`, `cwd`, `home` |
| остальные (внешние, MCP, скиллы) | `Action::"call"` | `Tool::"имя"` | `server`, `path`, `cwd`, `home` |

Команды bash-строки разбираются все: конвейеры, `$(...)`, `bash -c '...'` и обёртки — `sudo rm x`
даёт запросы и для `sudo`, и для `rm`; вердикт вызова — худший из них. `paths` — операнды,
похожие на пути, уже абсолютные и с раскрытыми симлинками: `rm -rf ~/`, `rm -rf "$HOME"` и
`rm -rf /home/me/../me/` дают один и тот же `context.home`, и правило одно. `File` лежит в
цепочке `Dir::"/a/b"` → `Dir::"/a"` → `Dir::"/"`; у домашнего каталога есть псевдоним `Dir::"~"`,
у текущего — `Dir::"."`, так что `resource in Dir::"~"` не зависит от машины (симлинк из `~`
наружу туда не попадает). `File` и `Tool` несут аргументы вызова как tags:
`resource.hasTag("private") && resource.getTag("private") == "false"` (не-строки — компактный JSON).
Для MCP-инструмента `Tool` лежит в `Server::"<сервер>"`.

Cedar — default deny: без `permit` запрещено всё, поэтому пример начинается с
`permit(principal, action, resource);` и дальше только запрещает. Движок fail-closed: ошибка
вычисления, отсутствие подходящего `permit` и файл `*.rego` в каталоге — это deny или ошибка
загрузки, а не разрешение. Политики проверяются по схеме при загрузке: опечатка в имени атрибута
(`context.comands`) — ошибка сразу, а не правило, которое молча не срабатывает.

`aish policy` загружает политики и печатает их число (или ошибку валидации);
`aish policy bash 'sudo ls'`, `aish policy write_file /etc/hosts` — спросить их об одном вызове без
модели, аргументы как у `aish tool`.

Пример `examples/policy/default.cedar` запрещает `sudo`, `rm -rf /` и `$HOME`, `git push --force`,
`exit`/`exec`, запись вне `$HOME` и спрашивает перед установкой пакетов.

## Хуки

Хук — исполняемый файл в `~/.config/aish/hooks/<событие>/` (каталог задаёт `hooks_dir` в
`config.toml`). На событие агента aish запускает хуки этого события по порядку имён, даёт каждому
на stdin JSON и читает ответ: JSON-объект или пустой stdout — ничего не менять. Как в Claude Code,
только без регистрации: положил файл с `chmod +x` — он работает со следующего запроса.

| событие | когда | вход (и везде `event`, `cwd`, `session`) | ответ |
|---|---|---|---|
| `user-prompt` | запрос, до модели | `prompt` | `{"context": "…"}` — дописать к запросу; `{"deny": "причина"}` — отклонить: запрос не уйдёт модели и не попадёт в журнал |
| `pre-tool` | вызов инструмента, после политики | что видит политика: `tool`, `args`, `commands`, `path`, `home`, `server`, `model`; `policy` — её вердикт, `{"action", "reason"}` | `{"action": "allow\|deny\|ask", "reason": "…"}`; `{"args": {…}}` — подменить аргументы |
| `post-tool` | результат инструмента, до записи | `tool`, `args`, `output`, `is_error` | `{"output": "…"}` — заменить результат |
| `stop` | запрос закончен | `text` — последний ответ, `steps`, `input_tokens`, `cached_tokens`, `output_tokens` | ничего, stdout не читается |

```sh
#!/bin/sh
# ~/.config/aish/hooks/pre-tool/no-sudo: ненулевой код — deny, stderr — причина
if grep -q sudo; then echo "sudo — только руками" >&2; exit 1; fi
```

```sh
#!/bin/sh
# ~/.config/aish/hooks/user-prompt/git-status: состояние репозитория к каждому запросу
s=$(git status --short --branch 2>/dev/null) || exit 0
jq -n --arg s "$s" '{context: ("git status:\n" + $s)}'
```

- **Политика — жёсткий дефолт, хук только ужесточает.** `pre-tool` идёт после политики; вызов,
  который она запретила, хуки не видят, а `allow` хука не отменяет её `ask`. Ненулевой код
  возврата `pre-tool` — deny с stderr в качестве причины: её видят и ты (`✗ denied by hook
  no-sudo: …`), и модель. Подменённые `args` получает следующий хук, и политика проверяет их
  заново — из двух вердиктов берётся строгий; в терминале команда уже подменённая.
- Хуки одного события идут друг за другом: `output` одного `post-tool` — вход следующего, первый
  deny останавливает остальные. Хуки проекта (`hooks_dir` в `.aish.toml`, относительно файла,
  например `.aish/hooks`) идут после личных.
- `post-tool` для `bash` срабатывает, когда вывод пришёл от shell; `output` — то, что получит
  модель, со строкой `[exit N, cwd …]`. Терминал показывает вывод как был и под ним строку
  `(the model gets the result as post-tool/… left it)`.
- Хук запускается в каталоге и с окружением shell (экспортированные переменные видны), в своей
  группе процессов. На хук 5 секунд: дольше — группа убивается, запрос идёт дальше. Ошибка хука
  (не запустился, таймаут, ненулевой код у других событий, ответ не JSON или с незнакомым ключом)
  — dim-строка в терминале, хук пропускается, запрос не падает. Ctrl+C обрывает и хук.
- Каталоги читаются один раз на запрос. Файл без `+x` и каталог, названный не по событию, тоже
  дают dim-строку: охранник, который молча не запускается, хуже. Файлы прямо в `hooks/` (общие
  библиотеки хуков) и скрытые пропускаются.

Пример `examples/hooks/post-tool/mask-secrets` (нужен `jq`) прячет в результатах ключи AWS
(`AKIA…`) и токены GitHub (`ghp_…`). Встроенная маскировка (`mask_defaults`) и так прячет их от
модели при отправке; хук не пускает их и в журнал сессии — и это место для своих правил.

## Настройки

`~/.config/aish/config.toml` (путь — `$AISH_CONFIG`), все ключи необязательны:

```toml
provider = "anthropic"            # или "openai" (Chat Completions), "openai-responses" (Responses API)
base_url = "http://127.0.0.1:8317" # прокси, например cliproxyapi; нет — официальный API провайдера
api_key_env = "AISH_API_KEY"
model = "claude-opus-5"           # или $AISH_MODEL
effort = "high"                   # low … max (у OpenAI ещё none, minimal); нет — уровень модели; или $AISH_EFFORT
max_tokens = 0                    # лимит ответа; 0 — 32000, на effort xhigh/max — 64000
profile = "work"                  # профиль [profiles.work] поверх ключей выше (см. ниже); или $AISH_PROFILE
max_steps = 50                    # шагов агента на один запрос; 0 — без ограничения
max_output_bytes = 16000          # сколько вывода команды видит LLM (голова + хвост); 0 — весь
mask = ["corp-[0-9a-f]{32}"]      # свои регулярки секретов, которые LLM видит как corp***; группа прячет только себя
mask_defaults = true              # встроенные регулярки (AWS, GitHub, OpenAI, Slack, PRIVATE KEY, password=…)
fold_lines = 0                    # сколько строк вывода агента показывать до сворачивания (-1 — не сворачивать)
journal_ignore = ["*secret*", "env", "printenv", "cat *credentials*", "history"]  # команды без вывода в журнале
state_ignore = ["*TOKEN*", "*SECRET*", "*KEY*", "*PASSWORD*", "AWS_*"]            # переменные вне <id>.state
markdown = true                   # рендерить ответы как markdown (false — как есть)
code_style = "monokai"            # стиль подсветки кода: https://xyproto.github.io/splash/docs/
prompt_status = true              # статус контекста справа от промпта
context_window = 0                # размер окна модели в токенах; 0 — узнать у API
compact_at = 0.8                  # доля окна, за которой сессия сжимается в сводку сама; 0 — никогда
mcp_config = "~/.config/aish/mcp.yaml"
shell = "/opt/bash/bin/bash"      # какой bash запускать; нет — $SHELL, если это bash, иначе первый bash в PATH
system_prompt = "Дополнение к системному промпту"
```

Провайдер — это протокол API. `openai` (Chat Completions) понимают и совместимые серверы —
Ollama, vLLM, LM Studio (`base_url` можно без `/v1`), но рассуждения модели между ходами он
теряет. `openai-responses` — Responses API OpenAI для моделей с рассуждением (gpt-5, o-серия):
рассуждения приходят зашифрованными, лежат в журнале и уходят обратно со следующим ходом, как
thinking-блоки у `anthropic`; у OpenAI при этом ничего не хранится (`store: false`). Ключ, если
нет ни `api_key`, ни переменной из `api_key_env`, берётся из переменной провайдера:
`ANTHROPIC_API_KEY` или `OPENAI_API_KEY`.

Профили — несколько endpoint'ов в одном файле: рабочий прокси, личный ключ, локальная Ollama.
Таблица `[profiles.ИМЯ]` накладывается на верхний уровень, а не заменяет его: незаданные в ней
ключи берутся оттуда, пустая таблица — сам верхний уровень. Кроме ключа API: свой `api_key` или
`api_key_env` в профиле заменяет оба ключа верхнего уровня, а профиль, который задаёт `provider`
или `base_url`, но не ключ, берёт его из переменной провайдера — ключ одного endpoint'а не уходит
на другой. В профиле бывают `provider`,
`base_url`, `api_key`, `api_key_env`, `model`, `effort`, `max_tokens` и `context_window`. Действует
профиль из `$AISH_PROFILE`, иначе из `profile`; нет ни того, ни другого — только верхний уровень,
как в конфиге без профилей. `$AISH_MODEL` и `$AISH_EFFORT` — поверх выбранного профиля. В shell
профиль переключает `aish model ИМЯ` (см. «Контекст и модель»).

```toml
profile = "work"

[profiles.work]
provider = "anthropic"
base_url = "http://127.0.0.1:8317"
api_key_env = "AISH_API_KEY"
model = "claude-opus-5"

[profiles.local]
provider = "openai"
base_url = "http://localhost:11434"
model = "qwen3:32b"
context_window = 32000            # Ollama не сообщает размер окна
```

Опечатка в имени ключа (и внутри `[profiles.ИМЯ]`), неизвестный профиль или отрицательный лимит —
ошибка при запуске с указанием ключа и файла, а не молчаливое значение по умолчанию.

### Настройки проекта

В репозитории может лежать `.aish.toml` — он накладывается на `config.toml` для запросов из
этого репозитория. Файл ищется от текущего каталога вверх: берётся ближайший, но не выше корня
git-репозитория (каталога с `.git`) и не в `~` — домашний каталог не проект, для него есть
`config.toml`. Ищется на каждый запрос, по каталогу shell: `cd` в другой репозиторий — другие
настройки. `aish status` показывает оба файла в строке `config`; `aish tool` видит инструменты
проекта.

Разрешены только ключи, которые не тратят чужие деньги и не уводят трафик: `system_prompt`,
`max_steps`, `max_output_bytes`, `fold_lines`, `markdown`, `code_style`, `policy_dir`, `[policy]`
(списки складываются с глобальными, из двух `write_outside_home` берётся строгий), `tools_dir`,
`hooks_dir` (см. «Хуки»).
`system_prompt` **дописывается** к глобальному, `policy_dir` и `tools_dir` **добавляются** к
глобальным каталогам (политики действуют из обоих; инструмент проекта с именем личного
пропускается), относительные пути — от каталога с `.aish.toml`; остальные ключи заменяют значение.
`provider`, `base_url`, `api_key*`, `model`, `effort`, `max_tokens`, `shell`, `sessions_dir`,
`mcp_config`, `context_window`, `profile` и `[profiles.*]` в `.aish.toml` запрещены: склонированный
репозиторий не должен выбирать, куда и за чей счёт уходят запросы. Запрещённый или незнакомый
ключ — ошибка с именем ключа и файла, запрос не выполняется.

```toml
# .aish.toml в корне репозитория
system_prompt = "Это Go-сервис; тесты гонять через make test, не go test."
tools_dir = "tools/aish"       # относительно этого файла
policy_dir = ".aish-policy"
max_output_bytes = 32000
```

## Как это устроено

```
терминал ⇄ aish (PTY-прокси, журнал сессии, агент: LLM, инструменты, политики; unix-сокет $AISH_SOCK)
               ⇅ байты насквозь; маркеры OSC 6973 вырезаются
           bash --rcfile <rc>     rc = source ~/.bashrc + init.bash
               Enter → bind -x __aish_route → текст: строка → __aish_ask '…'
                                              ⇅ JSON-RPC
                         aish agent start/resume (передаёт запрос агенту в прокси и ждёт)
```

aish — прокси между терминалом и bash: байты идут насквозь, а служебные маркеры, которые печатает
`init.bash`, вырезаются. По ним прокси знает, где начался и закончился вывод каждой команды, и пишет
его в журнал, очищенным от ANSI; вывод полноэкранных программ (vim, htop) не сохраняется. Enter
перехватывает `bind -x`: строка либо уходит bash как есть, либо превращается в `__aish_ask '…'`,
которая передаёт запрос агенту. Агент живёт в самом прокси, вместе с журналом, политиками и
MCP-серверами, поэтому шаг не зависит от размера сессии; `aish agent start` в shell лишь держит
соединение, пока прокси работает, — `Ctrl+C` по нему и останавливает агента. Команду `bash` агента
исполняет та же `__aish_ask` через `eval` в текущем shell — поэтому `cd` и `export` сохраняются.
