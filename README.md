# aish — LLM внутри твоего bash

`aish` запускает твой обычный bash (с `~/.bashrc`, алиасами, PS1, историей) в прозрачном PTY и перехватывает ввод **до того, как bash его разберёт**:

- текст с заглавной буквы → отвечает LLM, которая видит всю сессию: твои команды с их выводом и прошлый диалог;
- всё остальное → исполняет bash, как всегда.

```
$ make
main.go:12: undefined: foo
? Почему не собирается?
⚙ read_file main.go
❯ grep -rn "func foo" .  (1 line · ctrl+o to expand)
В main.go вызывается foo(), но функция нигде не объявлена…
```

## Установка

```sh
go build -o ~/.local/bin/aish ./cmd/aish
export AISH_API_KEY=...        # ключ cliproxyapi (или ANTHROPIC_API_KEY / OPENAI_API_KEY)
aish                           # новая сессия;  aish --resume — продолжить последнюю
```

Чтобы открывать aish в каждом терминале — запускай его как команду терминала (или `exec aish` в конце `~/.bashrc` под условием `[[ -z $AISH_SOCK && $- == *i* ]]`).

## Как определяется, что это текст

Запрос к LLM начинается с заглавной буквы: `Как найти большие файлы?`, `Find big files`. Всё остальное, включая опечатки (`gti status`) и текст со строчной буквы, уходит в bash. Если строка с заглавной буквы — реальная команда (алиас, функция, программа из `PATH`, например `Rscript`), её тоже выполняет bash. Для заглавных букв нужна UTF-8-локаль.

- `?текст` — всегда LLM (например `?почему не собирается`);
- `@файл` в начале строки — тоже LLM (`@main.go что тут происходит?`);
- `!команда` — всегда bash (`!!`, `!$`, `!-2`, `!12` остаются history expansion);
- в историю запрос сохраняется так, как ты его набрал: `Привет` — как `Привет`, `?почему` — с `?` (без него он ушёл бы в bash);
- в строке запроса `$` (или `#`) в конце промпта заменяется на `?`: `user@host:~? Почему не собирается?`.

## Агент

LLM работает автономно, без подтверждений. Инструменты:

| инструмент | что делает |
|---|---|
| `bash` | команда исполняется **в твоём живом shell**: `cd`, `export`, функции сохраняются, вывод свёрнут |
| `read_file PATH [OFFSET] [LIMIT]` | чтение с номерами строк |
| `write_file PATH [CONTENT\|-]` | запись (содержимое со stdin) |
| `edit_file PATH OLD NEW [REPLACE_ALL]` | точная замена строки |
| свои | исполняемые файлы в `~/.config/aish/tools/` |

Файлы можно приложить к запросу прямо в тексте: `Изучи заметки @*.md и расскажи по пунктам, что делать`. Под запросом появится строка на каждый файл, `@todo.md (12 lines)`, и модель получит их содержимое сразу, без `read_file`.

- `@путь` — файл (с номерами строк, как в `read_file`) или папка (список файлов); `~` раскрывается, относительные пути — от текущей папки;
- `@шаблон` — glob: `*`, `?`, `[…]` и `**` для любой глубины (`@src/**/*.go`); скрытые файлы, `.git` и `node_modules` — только если указаны явно (`@.github/**/*.yml`);
- путь с пробелами — в кавычках: `@"мои заметки.md"`; знак препинания после упоминания (`@a.go,`) к пути не относится, `user@host` упоминанием не считается;
- бинарные файлы не прикладываются; один файл — до 40 KB, все вместе — до 200 KB и 50 файлов, остальное модель дочитает сама;
- если ничего не нашлось, под запросом будет `@x.md: no such file`.

Инструменты — это команды: `read_file main.go 1 20` можно набрать самому. `aish tool` — список.

Свой инструмент — любой исполняемый файл с шапкой (см. `examples/tools/weather`):

```sh
#!/bin/sh
# aish:desc Show the weather forecast for a city
# aish:arg city string City name
# aish:arg days? integer Optional argument
# aish:arg body stdin Passed on standard input
```

Аргументы передаются позиционно и как `$AISH_ARG_<NAME>`.

`Ctrl+C` прерывает и генерацию, и команду агента; LLM увидит, что её прервали.

## Экран

- Ответы модели рендерятся как markdown прямо по мере генерации: строка, которая ещё пишется, видна как есть и перерисовывается, когда закончена.
  - Заголовки жирные, списки с `•`/`◦` и ☐/☑, цитаты с `│`, `---` — линия, ссылки как `текст (url)`, **жирный**, *курсив*, ~~зачёркнутый~~ и `код` в тексте.
  - Блоки кода подсвечиваются по языку (chroma, стиль `code_style`), строки ```` ``` ```` убираются.
  - Таблицы появляются целиком, когда закончились, в рамке; если не влезают по ширине, текст в ячейках переносится.
  - Абзацы и пункты переносятся по словам под ширину терминала с отступом.
- Пока модель думает, на экране крутится спиннер `⠋ thinking…`. Он появляется и тогда, когда модель замолкает посреди ответа, например пока пишет большой вызов инструмента.
- Вывод команд агента скрыт: на экране только сама команда, а справа от неё статус `(30 lines · exit 1 · ctrl+o to expand)`. Пока команда работает, счётчик строк обновляется.
  - Длинная команда переносится на несколько строк, и в конце последней строки пишется короткий статус: `(287 lines)`, без подсказки про Ctrl+O. Если справа не хватает места, статус переносится на следующую строку. `fold_lines = N` показывает первые N строк, `fold_lines = -1` выключает сворачивание.
- Ctrl+O открывает полноэкранный просмотр всего, что было свёрнуто за текущий или последний запрос, включая результаты `read_file` и выполняющуюся команду. Повторное нажатие Ctrl+O (или `q`/Esc) закрывает его, и экран возвращается как был.
  - Работает в любой момент: пока модель думает, пишет ответ или выполняет команду. Вывод за это время появится после закрытия.
  - Прокрутка: ↑↓ / j k, PgUp PgDn / пробел b, g G.
  - Если свёрнутого нет, Ctrl+O получает readline или запущенная программа, как обычно.
  - `aish expand` печатает свёрнутое прямо в терминал.
- `clear`, `reset` и Ctrl+L начинают сессию заново: после очистки экрана ассистент видит только то, что видно на экране. Очистка внутри полноэкранных программ (vim, less) не считается. Каждая очистка начинает новый файл журнала, даже несколько очисток подряд в одну секунду.
- Справа от промпта видно, сколько контекста занято, и текущая модель: `34k/1.0M 3% · claude-opus-5`. От 70% строка жёлтая, от 90% красная. Это подсказка, что пора сделать `aish compact` или `clear`.
  - Строку рисует aish, а не `PS1`, поэтому она уживается с любым промптом (starship и т. п.). В многострочном промпте она стоит на первой строке. Если терминал узкий, строки нет.
  - Видна, пока ждёт промпт: после Enter строка ввода перерисовывается и статус пропадает.
  - Выключается через `prompt_status = false`.
  - Размер считается так: точное число токенов последнего ответа модели плюс оценка (≈4 байта на токен) всего, что появилось после него. Окно модели берётся из API (`/v1/models`) или из `context_window`.

## Контекст и модель

- `aish compact [о чём помнить]` просит модель кратко изложить сессию: запросы, что сделано, пути, ошибки, текущее состояние. Дальше модели отправляется только эта сводка и то, что было после неё. Журнал не стирается: `aish session show` показывает и сводку, и всё, что было до неё. Инструкции CLAUDE.md после compact загружаются заново.
- `aish status` показывает:
  - занятый контекст, его долю от окна и способ подсчёта (точный или оценка);
  - число команд и запросов с последнего compact;
  - сколько токенов потрачено за сессию;
  - провайдер, модель и её окно;
  - основные настройки и пути к конфигу, политикам, инструментам и MCP.
- `aish model` выводит список моделей, которые отдаёт API, с размером окна; текущая отмечена `*`. `aish model ИМЯ` переключает модель **для этого shell** до выхода из aish, имя проверяется по списку. Чтобы переключить насовсем, поменяй `model` в `config.toml`.

## Инструкции (CLAUDE.md)

Как в Claude Code, агент получает инструкции из файлов:

- глобальные: `~/.claude/CLAUDE.md`, `~/.config/aish/CLAUDE.md`;
- по папкам: `CLAUDE.md`, `.claude/CLAUDE.md`, `AGENTS.md`, `CLAUDE.local.md` в каждой папке от `/` до текущей.

Файлы читаются не при `cd`, а при первом запросе из папки: под запросом появляется строка `(путь к файлу)`. Каждый файл попадает в сессию один раз. Если он изменился, при следующем запросе модель получит новую версию. После `clear` инструкции загружаются заново.

## MCP-серверы

Инструменты MCP-серверов становятся командами shell: `github_search_issues "bug" --state open`. Их может набрать и пользователь, и агент (через `bash`). Серверы описываются в `~/.config/aish/mcp.yaml` (путь меняется `mcp_config` в `config.toml`; файла нет — MCP выключен):

```yaml
servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_TOKEN: ${GITHUB_TOKEN}   # переменные раскрываются
    timeout: 120                      # секунд на вызов, по умолчанию 60
  remote:
    url: https://example.com/mcp      # Streamable HTTP
    headers:
      Authorization: Bearer ${TOKEN}
    expose: tools                     # отдавать модели схемы как обычные инструменты
```

- Серверами владеет прокси: сервер запускается при первом вызове и живёт до выхода из shell. Список инструментов кэшируется в `~/.cache/aish/mcp/`, поэтому в следующих сессиях команды появляются сразу, без запуска сервера. Сервер, которого нет в кэше, при старте shell опрашивается в фоне.
- Имя команды — `<сервер>_<инструмент>`. Если такая команда уже есть в `PATH`, обёртка не создаётся (иначе она бы её подменила); причина видна в `aish tool`.
- Аргументы: обязательные строки и числа — позиционно, в порядке схемы; остальные — `--name значение`, булевы — `--name`, объекты и массивы — `--name '<json>'`. `NAME -h` показывает форму вызова.
- Вывод: текст — в stdout, картинки и бинарные данные сохраняются во временный файл и печатается путь. Ошибка инструмента или упавший сервер — ненулевой код возврата и сообщение (с концом stderr сервера).
- По умолчанию схемы MCP-инструментов модели не отправляются: в системном промпте одна строка про `aish tool`, и модель находит их сама. `expose: tools` отдаёт схемы как обычным инструментам.
- Поддерживаются только инструменты (без resources, prompts, sampling). Транспорты — stdio и Streamable HTTP; старый HTTP+SSE (URL на `/sse`) не поддерживается.

## Политики (Rego)

Каждый вызов инструмента проверяется политиками из `~/.config/aish/policy/*.rego` (OPA). Запрос — `data.aish.decision`, результат `{"action": "allow"|"deny"|"ask", "reason": "..."}`; нет политик — всё разрешено. `deny` возвращается агенту с причиной, `ask` спрашивает тебя `[y/N]`.

`input`: `tool`, `args`, `cwd`, `home`, `path` (для файловых инструментов, абсолютный, симлинки раскрыты: `~/link/x` при `link → /etc` даёт `/etc/x`, в том числе для файла, которого ещё нет; `home` тоже раскрыт), `server` (для MCP-инструментов, вызванных моделью напрямую) и `commands` — argv каждой простой команды bash-строки, включая конвейеры, `$(...)`, `bash -c '...'` и обёртки (`sudo rm x` даёт и `["sudo","rm","x"]`, и `["rm","x"]`).

Пример — `examples/policy/default.rego`: запрет `sudo`, `rm -rf /`/`$HOME`, `git push --force`, `exit`/`exec`, записи вне `$HOME`; вопрос на установку пакетов.

## Настройки

`~/.config/aish/config.toml` (всё необязательно):

```toml
provider = "anthropic"            # или "openai" (Chat Completions)
base_url = "http://127.0.0.1:8317" # cliproxyapi
api_key_env = "AISH_API_KEY"
model = "claude-opus-5"           # или $AISH_MODEL
max_tokens = 32000
max_steps = 50                    # шагов агента на один запрос
max_output_bytes = 16000          # сколько вывода команды видит LLM (голова + хвост)
fold_lines = 0                    # сколько строк вывода агента показывать до сворачивания (-1 — не сворачивать)
markdown = true                   # рендерить ответы как markdown (false — как есть)
code_style = "monokai"            # стиль подсветки кода: https://xyproto.github.io/splash/docs/
prompt_status = true              # статус контекста справа от промпта
context_window = 0                # размер окна модели в токенах; 0 — узнать у API
mcp_config = "~/.config/aish/mcp.yaml"
system_prompt = "Дополнение к системному промпту"
```

Сессии — `~/.local/share/aish/sessions/*.jsonl`. `aish session show` / `aish session clear`, `aish compact`, `aish status`, `aish model`.

## Устройство

```
терминал ⇄ aish (PTY-прокси, журнал сессии, unix-сокет $AISH_SOCK)
               ⇅ байты насквозь; маркеры OSC 6973 вырезаются
           bash --rcfile <rc>     rc = source ~/.bashrc + init.bash
               Enter → bind -x __aish_route → текст: строка → __aish_ask '…'
                                              ⇅
                         aish agent start/resume (LLM, инструменты, политики)
```

- Вывод команд пользователя пишется между маркерами `PS0` (старт) и `PROMPT_COMMAND` (конец), очищается от ANSI/`\r`; полноэкранные программы (vim, htop) помечаются, вывод не сохраняется.
- Команду `bash` агента выполняет сама функция `__aish_ask` в текущем shell через `eval`, прокси захватывает её вывод и отдаёт агенту.
