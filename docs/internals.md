# Как это устроено

Как aish устроен внутри — для того, кто читает код.

```
терминал ⇄ aish (PTY-прокси, журнал сессии, агент: LLM, инструменты, политики; unix-сокет $AISH_SOCK)
               ⇅ байты насквозь; маркеры OSC 6973 вырезаются
           bash --rcfile <rc>     rc = source ~/.bashrc + init.bash
               Enter → bind -x __aish_route → текст: строка → __aish_ask "$__aish_req"
                                              ⇅ JSON-RPC
                         aish agent start/resume (передаёт запрос агенту в прокси и ждёт)
```

aish — прокси между терминалом и bash: байты идут насквозь, а служебные маркеры, которые печатает
`init.bash`, вырезаются. По ним прокси знает, где начался и закончился вывод каждой команды, и пишет
его в журнал, очищенным от ANSI; вывод полноэкранных программ (vim, htop) не сохраняется. Enter
перехватывает `bind -x`: строка либо уходит bash как есть, либо превращается в `__aish_ask "$__aish_req"`
(текст — в `__aish_req`), которая передаёт запрос агенту. Агент живёт в самом прокси, вместе с журналом, политиками и
MCP-серверами, поэтому шаг не зависит от размера сессии; `aish agent start` в shell лишь держит
соединение, пока прокси работает, — `Ctrl+C` по нему и останавливает агента. Команду `bash` агента
исполняет та же `__aish_ask` через `eval` в текущем shell — поэтому `cd` и `export` сохраняются.
С zsh всё так же, только shell — `zsh -i` с `ZDOTDIR` прокси, чей `.zshrc` читает твой и `init.zsh`,
а Enter перехватывает обёртка виджета `accept-line`.

Главные части кода:

- `cmd/aish` — разбор аргументов и все подкоманды;
- `internal/proxy` — прокси: PTY, маркеры, журнал, экран, unix-сокет и агент, который в нём живёт;
- `internal/shellinit` — `init.bash` и `init.zsh`, вся интеграция с shell'ом;
- `internal/agent` — цикл запроса: ход модели, вызовы инструментов, команда для shell'а или ответ;
- `internal/llm` — провайдеры моделей;
- `internal/tools`, `internal/mcp`, `internal/skills`, `internal/subagent`, `internal/hooks` — встроенные и свои
  инструменты, MCP-серверы, скиллы, сабагенты, хуки;
- `internal/policy` — политики: Cedar, правила `[policy]`, разбор командной строки;
- `internal/session`, `internal/shellstate` — журналы сессий и состояние shell'а;
- `internal/config` — `config.toml`, `.aish.toml` и доверие к нему.

Роль каждого пакета описывает его godoc-комментарий: `go doc ./internal/proxy`.
