# Хуки

Как вмешаться в работу ассистента своими исполняемыми файлами: дополнить запрос, запретить или подменить вызов
инструмента, заменить его результат.

Хук — исполняемый файл в `~/.config/aish/hooks/<событие>/` (каталог задаёт `hooks_dir` в
`config.toml`). На событие агента aish запускает хуки этого события по порядку имён, даёт каждому
на stdin JSON и читает ответ: JSON-объект или пустой stdout — ничего не менять. Как в Claude Code,
только без регистрации: положил файл с `chmod +x` — он работает со следующего запроса.

| событие | когда | вход (и везде `event`, `cwd`, `session`; у сабагента ещё `agent`, `agent_id`, `parent_session`) | ответ |
|---|---|---|---|
| `user-prompt` | запрос, до модели | `prompt` | `{"context": "…"}` — дописать к запросу: модель получит текст вместе с ним, с маскировкой секретов, как у вывода команд, а журнал хранит его отдельной записью, и `aish session show` его не печатает; `{"deny": "причина"}` — отклонить: запрос не уйдёт модели и не попадёт в журнал; у сабагента отказ — его ошибка: ассистент получит ответ сабагента со статусом `error` и причиной |
| `pre-tool` | вызов инструмента, после политики | что видит политика: `tool`, `args`, `line` (строка, отданная shell), `commands`, `parse_error`, `dynamic`, `writes` (файлы, в которые пишут редиректы строки), `path`, `home`, `server`, `model`, `agent` (имя сабагента, у основного агента нет); `policy` — её вердикт, `{"action", "reason"}` | `{"action": "allow\|deny\|ask", "reason": "…"}`; `{"args": {…}}` — подменить аргументы |
| `post-tool` | результат инструмента, до записи | `tool`, `args`, `output`, `is_error` | `{"output": "…"}` — заменить результат |
| `stop` | запрос закончен | `text` — последний ответ, `steps`, `input_tokens`, `cached_tokens`, `output_tokens` | ничего, stdout не читается |

```sh
#!/bin/sh
# ~/.config/aish/hooks/pre-tool/no-sudo: ненулевой код — deny, stderr — причина
if grep -q sudo; then echo "sudo — только руками" >&2; exit 1; fi
```

```sh
#!/bin/sh
# ~/.config/aish/hooks/user-prompt/git-status: состояние репозитория к каждому запросу
s=$(git status --short --branch 2>/dev/null) || exit 0
jq -n --arg s "$s" '{context: ("git status:\n" + $s)}'
```

- **Политика — жёсткий дефолт, хук только ужесточает.** `pre-tool` идёт после политики; вызов,
  который она запретила, хуки не видят, а `allow` хука не отменяет её `ask`. Ненулевой код
  возврата `pre-tool` — deny с stderr в качестве причины: её видят и ты (`✗ denied by hook
  no-sudo: …`), и модель. Подменённые `args` получает следующий хук, и политика проверяет их
  заново — из двух вердиктов берётся строгий; в терминале команда уже подменённая.
- События сабагента (см. [«Сабагенты»](../README.md#сабагенты)) идут в те же хуки. `session` у них —
  `sub:ИМЯ` у всех запусков одного сабагента, а различают их поля, которых у основного агента нет: `agent` — имя сабагента;
  `agent_id` — запуск: `ID.N` у того, кого ждёт вызов `task` (`ID` — id этого вызова в журнале
  сессии, `N` — номер задачи в нём, с 1: `toolu_01….2`), `bgN` у фонового (как в `task_wait` и
  `aish tasks`); `parent_session` — ID сессии aish, на которую он работает.
- Хуки одного события идут друг за другом: `output` одного `post-tool` — вход следующего, первый
  deny останавливает остальные. Хуки проекта (`hooks_dir` в `.aish.toml`, относительно файла,
  например `.aish/hooks`) идут после личных и только после `aish trust` (см.
  [«Настройки проекта»](../README.md#настройки-проекта)).
- `post-tool` для `bash` срабатывает, когда вывод пришёл от shell; `output` — то, что получит
  модель, со строкой `[exit N, cwd …]`. Терминал показывает вывод как был и под ним строку
  `(the model gets the result as post-tool/… left it)`.
- Хук запускается в каталоге и с окружением shell (экспортированные переменные видны), в своей
  группе процессов. На хук 5 секунд: дольше — группа убивается, запрос идёт дальше. Ошибка хука
  (не запустился, таймаут, ненулевой код у других событий, ответ не JSON или с незнакомым ключом)
  — dim-строка в терминале, хук пропускается, запрос не падает. Если `pre-tool` — охрана,
  `hooks_fail = "deny"` в `config.toml` превращает такую ошибку в запрет вызова (`hook failed: …`),
  как у политики. Ctrl+C обрывает и хук.
- Каталоги читаются один раз на запрос — и ещё раз, если посреди запроса доверие к проекту пропало:
  его хуки до конца запроса уже не запускаются. Файл без `+x` и каталог, названный не по событию, тоже
  дают dim-строку: охранник, который молча не запускается, хуже. Файлы прямо в `hooks/` (общие
  библиотеки хуков), скрытые и резервные копии редактора (`имя~`) пропускаются.
- `aish hooks` показывает, какие хуки сработают в этом каталоге, по событиям и в порядке запуска, и
  те же проблемы; хуки недоверенного `.aish.toml` в список не входят, вместо них — строка с подсказкой
  `aish trust`. В `aish status` — их число в строке `hooks`.

Пример `examples/hooks/post-tool/mask-secrets` (нужен `jq`) прячет в результатах ключи AWS
(`AKIA…`) и токены GitHub (`ghp_…`). Встроенная маскировка (`mask_defaults`) и так прячет их от
модели при отправке; хук не пускает их и в журнал сессии — и это место для своих правил.
