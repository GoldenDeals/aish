# MCP-серверы

Как подключить MCP-серверы и вызывать их инструменты.

Инструменты MCP-серверов называются `<сервер>_<инструмент>`. Модель вызывает их как обычные
инструменты (ниже — как она о них узнаёт), а сам их зовёшь через `aish tool`:
`aish tool github_search_issues "bug" --state open`.
Серверы описываются в `~/.config/aish/mcp.yaml` (путь меняется `mcp_config` в `config.toml`;
нет файла — MCP выключен):

```yaml
servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_TOKEN: ${GITHUB_TOKEN}   # переменные раскрываются
    timeout: 120                      # секунд на вызов, по умолчанию 60; вызов модели кончается и по своему сроку (см. README, «Что умеет ассистент»)
  tracker:
    command: npx
    args: ["-y", "tracker-mcp"]
    env_command:                      # значение — вывод команды
      TRACKER_TOKEN: pass show tracker/token
  remote:
    url: https://example.com/mcp      # Streamable HTTP
    headers:
      Accept-Language: ru
    headers_command:
      Authorization: echo "Bearer $(pass show example.com/token)"
    expose: tools                     # схемы модели сразу; по умолчанию deferred — через tool_search
```

Токен не обязательно держать в файле или экспортировать перед запуском aish: в `env_command` и
`headers_command` значение переменной или заголовка — вывод команды. Она идёт через `sh -c` в `~`, с
окружением aish и без stdin, до 30 секунд; конечный перевод строки отрезается, пустой вывод или
ненулевой код — ошибка старта сервера с концом stderr команды. Команды запускаются при каждом старте
сервера, вывод нигде не хранится, а в ошибках и в `aish mcp` скрыт, какой бы ни был ключ. Сервер с
такими командами при запуске aish в фоне не опрашивается: команды ждут первого обращения — вызова
или `aish tool`. Ключ не может быть сразу в `env` и `env_command` (`headers` и `headers_command`).
`pass` без ключа в кэше gpg-agent и без графического pinentry пароль здесь может не спросить —
разблокируй ключ до запуска aish (хотя бы `pass show … >/dev/null`).

- Сервер запускается при первом вызове и живёт до выхода из shell или до `aish apply-config`, после
  правки или удаления его в `mcp.yaml` (см. [«Настройки»](../README.md#настройки)). Список инструментов кэшируется в
  `~/.cache/aish/mcp/`, поэтому в следующий раз инструменты известны сразу. Сервер, которого нет в кэше,
  опрашивается в фоне при старте; модель увидит его инструменты со следующего запроса, `aish tool`
  дождётся старта.
- Аргументы — как у [своих инструментов](extending.md#свои-инструменты): обязательные строки, числа и булевы
  (`true`/`false`) — позиционно, остальное флагами `--name значение`, необязательные булевы — `--name`, объекты и
  массивы — JSON. `aish tool NAME -h` показывает форму.
- Текст идёт в stdout, картинки и бинарные данные — во временный файл, печатается его путь. Ошибка
  инструмента или упавший сервер — ненулевой код возврата и сообщение с концом stderr сервера.
- По умолчанию (`expose: deferred`) схемы MCP-инструментов в запрос не идут: модель видит в системном
  промпте их полные имена по серверам, загружает нужные инструментом `tool_search` — по именам или по
  словам из имени и описания — и дальше вызывает их как обычные инструменты, так что политика видит и
  инструмент, и его сервер; сам `tool_search` для политики — `Action::"call"` на `Tool::"tool_search"`.
  Загруженные остаются в запросе до сводки (`aish compact`, автокомпакт), `clear` или новой сессии.
  `expose: tools` отдаёт схемы сервера сразу, в каждом запросе, — для серверов с парой инструментов.
- Инструкции сервера (`instructions` из ответа на `initialize`) идут в системный промпт разделом
  «MCP Server Instructions», не длиннее 4 КБ на сервер, и кэшируются в `~/.cache/aish/mcp/` вместе со
  списком инструментов.
- `aish mcp` показывает состояние каждого сервера, транспорт, команду или URL (секреты скрыты),
  инструменты и, для упавших, ошибку. Внутри aish — серверы применённого `mcp.yaml` и его путь; правку,
  которую ещё не применил `aish apply-config`, он называет.
- Поддерживаются только инструменты (без resources, prompts, sampling), транспорты — stdio и
  Streamable HTTP; старый HTTP+SSE не поддерживается.
