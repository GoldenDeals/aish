# Терминальный UI: как рисовать из модуля

Терминалом владеет модуль-компоновщик [modules/frontend/tui](../modules/frontend/tui) (в конфиге — `tui`). Сам он ничего не рисует, а даёт API
для элементов. Модуль открывает элемент, указывая его вид (kind) и z. Ядро решает, где элемент окажется
и какого он будет размера. Внутри своего прямоугольника элемент рисует что хочет, а ячейки, которые он не задал,
прозрачны. Ввод идёт по z сверху вниз, пока его кто-нибудь не поглотит.

Контракт — `contracts/tui`. Ячейки, события и курсор берутся из
[ultraviolet](https://github.com/charmbracelet/ultraviolet) как есть. Поэтому элементом может быть любой
`uv.Drawable`: свой тип, виджет lipgloss/bubbles v2 или эмулятор терминала `x/vt`.

Модули по-прежнему общаются только через шину ([bus.md](bus.md)). Через шину модуль получает экран: событие
`tui.ready`. Отрисовка и ввод идут прямыми вызовами, потому что шина в каждый момент занята одной tx,
а `llm.answer` держит её до конца ответа. Если пустить нажатия и кадры через `Dispatch`, интерфейс
замер бы на всё время генерации.

## Быстрый старт

```go
import (
	uv "github.com/charmbracelet/ultraviolet"

	"github.com/GoldenDeals/aish-core/contracts/tui"
)

const zStatus = 100

// status — строка состояния внизу; текст приходит событием status.text.
type status struct {
	mu   sync.Mutex // Draw идёт из горутины компоновщика, set — из обработчика шины
	text string
	h    tui.Handle
}

func (s *status) Size(w, _ int) (int, int) { return w, 1 }

func (s *status) Draw(scr uv.Screen, area uv.Rectangle) {
	s.mu.Lock()
	defer s.mu.Unlock()
	uv.NewStyledString(s.text).Draw(scr, area) // StyledString закрашивает всю область: строка непрозрачна
}

func (s *status) set(text string) {
	s.mu.Lock()
	s.text = text
	h := s.h
	s.mu.Unlock()
	if h != nil {
		h.Redraw()
	}
}

// В Init(b bus.Bus, cfg config.Config), s := &status{}:
bus.Async(b, event.ByName(tui.Ready), func(_ context.Context, ev event.Event[tui.Screen]) {
	h := ev.Data().Open(tui.Pane, zStatus, s)
	s.mu.Lock()
	s.h = h
	s.mu.Unlock()
})
bus.Async(b, event.ByName("status.text"), func(_ context.Context, ev event.Event[string]) { s.set(ev.Data()) })
```

`tui.ready` приходит один раз из `Start` компоновщика. Это может случиться раньше твоего `Start`,
поэтому подписывайся в `Init`. Если tui не собран в бинарник, события не будет, и модуль просто работает без экрана.

## Виды элементов

| Kind | Где | Размер |
|---|---|---|
| `Pane` | во всю ширину, стеком у нижнего края | высота из `Size(width, свободные строки)` |
| `Fullscreen` | строки, оставшиеся над панелями; пока открыт хоть один, терминал в alt screen | всё, `Size` не спрашивается |
| `Overlay` | по центру кадра поверх всего, что ниже по z | `w×h` из `Size(width, height)` |
| `Text` | печатается один раз в scrollback над живой областью | высота из `Size(width, math.MaxInt)` |

- **Inline** (Fullscreen не открыт): кадр занимает внизу терминала столько строк, сколько нужно панелям,
  или больше, если какой-то Overlay выше. Всё, что над кадром, — обычный scrollback терминала.
- **Alt screen** (открыт хоть один Fullscreen): кадр — весь экран. Все Fullscreen-элементы получают один и тот же
  прямоугольник, кто сверху — решает z. Когда последний закрыт, терминал возвращается в inline.
- **Text** — то, что уже не будет меняться: готовое сообщение, вывод команды. Он не перерисовывается и не держит
  места в кадре; после печати элемент закрыт. В alt screen Text ждёт возврата на основной экран.
  Text, закрытый до своего кадра, не печатается.
- Без `Size` элемент берёт всё, что ему предлагают; Text без `Size` — высотой в экран. Ядро может дать меньше,
  чем просили: настоящий размер приходит в `Draw` (`area`).

## Порядок: z

Элементы упорядочены по z, при равном z выше тот, кого открыли позже. Чем выше элемент:
- тем позже он рисуется — перекрывает нижних там, где что-то нарисовал;
- тем раньше получает ввод;
- тем ближе к нижнему краю стоит среди панелей.

Раскладка в стиле Claude Code: статус-строка — самый высокий z среди панелей, под ней меню автодополнения,
над ним поле ввода, выше разговор, а диалоги — Overlay с z выше всех. Держи z именованными константами:
порядок опирается на чужие числа, как приоритеты на шине.

## Элемент

```go
type Drawable interface { Draw(scr uv.Screen, area uv.Rectangle) } // обязателен (uv)

type Sizer interface    { Size(width, height int) (w, h int) } // сколько хочет из доступного
type Receiver interface { Input(ev uv.Event) bool }            // true — поглотил
type Cursorer interface { Cursor() *uv.Cursor }                // где показать курсор терминала
```

- **`Draw`** рисует в своих координатах: `area == scr.Bounds()`, начало в (0,0), за край нарисовать нельзя.
  Незаданные ячейки прозрачны; нужен фон — залей его. На каждом кадре `Draw` зовётся заново и рисует всё.
- **`Input`** получает нажатия (`uv.KeyPressEvent`, удобно `k.MatchString("ctrl+o")`), вставку
  (`uv.PasteEvent`, bracketed paste включён) и прочие события терминала, кроме смены размера.
  В alt screen включена мышь, с перетаскиванием: события мыши (`uv.MouseClickEvent`, `uv.MouseMotionEvent`,
  `uv.MouseWheelEvent` и др.) идут по z, как клавиши, в координатах терминала, а не элемента.
  Компоновщик включает kitty keyboard protocol (disambiguate): где терминал его знает, `shift+enter`, `ctrl+i`
  и подобные приходят отдельно от `enter`, `tab`; в остальных терминалах они неотличимы.
  Сам ввод кадр не рисует: изменил состояние — вызови `Redraw`.
  Элемент нулевого размера невидим, но стоит в цепочке ввода: так модуль заводит глобальный хоткей.
- **`Cursor`** возвращает курсор в координатах элемента (`uv.NewCursor(x, y)`) или nil. Показывается курсор
  самого верхнего элемента, вернувшего не nil; курсор за пределами элемента не показывается.
  Если курсора нет ни у кого, он скрыт.
- **`Handle.Redraw()`** просит новый кадр. Кадр рисуется только по изменению: открытие, закрытие, `Redraw`,
  смена размера терминала. Вызовы, пришедшие во время отрисовки, схлопываются в один следующий кадр,
  поэтому поток `Redraw` (например, вывод PTY) рисуется с той скоростью, с какой терминал принимает вывод.
  **`Handle.Close()`** убирает элемент. Оба метода можно вызывать повторно и после закрытия.
- **`Screen.Copy(text)`** кладёт текст в системный буфер обмена. Под tmux это `tmux load-buffer -w`: OSC 52
  от панели tmux по умолчанию (`set-clipboard external`) отбрасывает, а так текст попадает и в буфер tmux.
  Без tmux — OSC 52. Средняя кнопка или `ctrl+v`, которые не поглотил ни один элемент, вставляют скопированное
  как `uv.PasteEvent`, как терминал вставляет своё выделение: под tmux — его буфер (`tmux paste-buffer -p`),
  куда попадает и `Copy`, и копирование мышью в других панелях; без tmux — последний `Copy`. Не блокирует.
  Ctrl+Shift+V — вставка самого терминала, до приложения доходит готовым `uv.PasteEvent`.

## Потоки

- `Draw`, `Size`, `Input` и `Cursor` вызываются по очереди из одной горутины компоновщика.
  Состояние, которое меняют твои обработчики шины, защищай мьютексом.
- Блокировать там нельзя: пока ты внутри, интерфейс стоит. `Dispatch` ждёт открытую tx, а стрим `llm.answer`
  держит её до конца ответа. Поэтому из `Input` — только `go b.Dispatch(...)`.
- `Open`, `Redraw` и `Close` не блокируют и безопасны из любой горутины, в том числе из `Draw` и `Input`.
- Пока работает tui, в stdout/stderr не пишем: это ломает кадр. Выводи через Text.

## Ввод и выход

Событие идёт от верхнего элемента к нижнему, пока какой-нибудь `Input` не вернёт true.
Если `ctrl+c` никто не поглотил, процесс получает SIGINT и все модули штатно останавливаются: в raw mode
терминал сам SIGINT не шлёт. Модальный диалог, который поглощает всё, поглощает и `ctrl+c`.
`tui.inputline` поглощает `ctrl+c`, пока ответ модели идёт, и останавливает его; без ответа — выход.

На выходе терминал возвращается в исходный режим. Последний inline-кадр остаётся на экране, промпт shell
появляется под ним. Если выходим из alt screen, устаревший inline-кадр стирается.

## Рендереры

Содержимое (сообщения, ответы, вывод тулов) рисует ядро рендереров
[modules/frontend/tui/renderer](../modules/frontend/tui/renderer) по правилам, которые задают рендереры.

**Для модуля, который показывает контент**, контракт — `contracts/tui/renderer`. Шина здесь не нужна:

```go
b := renderer.New(renderer.Markdown) // пустой блок; nil, если ядро не собрано в бинарник

type Block interface {
	uv.Drawable  // рисует себя в area; area может выходить за экран — лишнее обрезается
	tui.Sizer    // сколько строк на ширине: Size(width, math.MaxInt)
	Write(chunk string) // дописать, пока контент стримится
}
```

Kind задаёт источник. У `llm.answer` kind `markdown`: ответ разбирается по правилам. У сообщения пользователя
и ошибок kind `text`: текст показывается как есть. У вызова тула kind `tool`: строка с именем тула и его входом
в JSON, а когда вызов закончился — строка `ok` или `error` и вывод. Такой kind рисует целиком функция, которую рендерер
регистрирует через `renderer.Kind(kind, draw)`; без неё блок показывается как есть. Блоки не скроллят: владелец спрашивает их высоты и рисует
видимые со сдвигом. Блок можно открыть и как tui-элемент: открытый как `Text`, он печатается в scrollback.

**Рендерер** — Go-пакет под `modules/frontend/tui/renderer/`. Модулем шины он не является: он импортирует ядро
и регистрирует свои правила из `init()`, как модуль регистрирует себя в `module.Register`:

```go
func init() {
	renderer.Register(
		renderer.Rule{Open: `^(#{1,6}) +`, Close: `\n`, Nested: true, Draw: heading},
		renderer.Rule{Open: `\*\*`, Close: `\*\*`, Abort: `\n`, Nested: true, Draw: bold},
		renderer.Rule{Open: "^( *)```([\\w+#.-]+)[^\\n]*\\n", Close: "^ *```", Draw: code},
	)
}

func bold(z renderer.Zone, width int) string {
	return renderer.Styled(uv.Style{Attrs: uv.AttrBold}, z.Inner(width))
}
```

- **Зона** — текст от совпадения `Open` до следующего совпадения `Close`; без `Close` зона — само совпадение
  `Open` (эмодзи, линия, экранирование). Выражения — regexp; `^` и `$` совпадают в начале и конце строки.
  Переносы строк в конце совпадения `Close` остаются вне зоны: заголовок закрывается на `\n` и оставляет его тексту вокруг.
- **Вложенность.** Текст зоны с `Nested` разбирается дальше: `# Today is *good* day` — зона заголовка, а в ней
  зона курсива. Без `Nested` текст попадает в `Draw` сырым (код, формулы, диаграммы).
- **Специфичность.** Если на одном месте совпало несколько выражений, первым пробуется самое специфичное:
  то, любое совпадение которого содержит больше буквальных символов, а при равенстве — более длинное совпадение.
  ```` ```mermaid ```` (11) специфичнее ```` ```\w+ ```` (4), а та — ```` ``` ```` без языка (4, но короче).
  `Close` и `Abort` текущей зоны при равенстве идут раньше чужих `Open`. `Open`, чья зона не закрылась,
  уступает следующему кандидату: `**b *i***` — это жирный с курсивом внутри.
- **Abort.** Если `Abort` нашёлся раньше `Close`, `Open` остаётся простым текстом. Если текст кончился раньше
  `Close`, зона правила с `Abort` тоже остаётся текстом: `**` без пары не прячется. Зона без `Abort` при этом
  остаётся с `Zone.Close == nil`, поэтому блок кода виден, пока стримится. Зона правила с `Abort` без текста —
  не зона: `**` не пустой курсив, а `>` — пустая строка цитаты.
- **Draw** возвращает стилизованный текст (SGR, `\n`); строки, которые он делает сам, не шире `width`.
  `z.Inner(width)` — текст зоны с нарисованными вложенными зонами. `renderer.Styled` накладывает стиль так,
  что стили вложенных зон складываются с ним. `renderer.Indent` делает отступ и жёсткий перенос, как у блока кода.
  Ядро запоминает нарисованные зоны, поэтому закрытая диаграмма не перерисовывается на каждом кадре.
- **Стрим.** Блок разбирает весь текст на каждой раскладке: текст только растёт, поэтому разбор верен
  в любой точке стрима.
- **Безопасность.** Текст недоверенный. `uv.StyledString` разбирает escape-последовательности: SGR превращает
  в стиль, а APC/DCS пропускает в терминал. Поэтому ядро выбрасывает управляющие символы до того, как текст
  увидят правила, и `\x1b[31m` виден как `[31m`. Паника в `Draw` (например, в чужой библиотеке на странной
  формуле) показывает исходник зоны вместо падения процесса.

## Курсор модели

Контракт — `contracts/tui/caret`. Разговор (`tui.fullscreen`) объявляет из `Start` событием `tui.caret.announce`
`caret.Source`: `Last()` — ячейка последнего символа на последнем кадре (у широкого — правая половина); `X == -1`,
если последний блок ещё пуст: его текст начнётся со строки `Y`; `false`, если вид не на конце.
Модуль-маркер (`tui.thinking`) открывает свой `Fullscreen` с z выше разговора: все Fullscreen получают одну область,
незаданные ячейки прозрачны, а нижний z рисуется раньше, поэтому `Last()` из его `Draw` — уже этого кадра.
Без Source маркер ничего не открывает: один его Fullscreen увёл бы терминал в alt screen.

## Три сценария

**Полноэкранный харнесс.**
- Разговор — `Fullscreen`, z 0; прокручивает себя сам (PgUp/PgDn и ↑/↓ в `Input`).
- Поле ввода — `Pane`: высота из `Size` по переносам текста, `Cursor`; на Enter — `go Dispatch(user.message)`.
- Статус — `Pane` с z выше поля ввода, `Size` → 1.
- Разрешение тула — `Overlay` с самым высоким z: поглощает всё, по y/n закрывается и шлёт
  `go Dispatch(permission.response)`.

**Inline-чат.** Fullscreen не открываем.
- Готовые сообщения — `Text`.
- Ответ, пока стримится, — растущая `Pane`. Sync-подписка на `llm.answer` читает стрим в горутине
  (как в [bus.md](bus.md#стримы)) и на каждый чанк зовёт `Redraw`.
- Когда стрим кончился — `Close` у панели и `Text` с полным ответом. Поле ввода и статус — тоже `Pane`.

**PTY-прокси к bash.**
- Bash — `Fullscreen`: `Draw` → `vt.Emulator.Draw`, `Input` → `SendKey`/вставка в эмулятор (он сам кодирует клавиши
  под режимы программы), `Cursor` → курсор эмулятора.
- Горутина читает pty, пишет в эмулятор и зовёт `Redraw`.
- Если размер в `Draw` не совпал с эмулятором — `pty.Setsize` и resize эмулятора.
- AI-попап — `Overlay`. Открывает его невидимый элемент-хоткей с высоким z.

## Ограничения

- Мышь включена только в alt screen: иначе tmux с `mouse on` не отдаёт колесо приложению. Поэтому выделение
  там своё: fullscreen выделяет drag'ом и копирует через `Screen.Copy`, средняя кнопка вставляет.
  Выделение самого терминала — Shift+drag. Inline мышь выключена: колесо и выделение остаются у терминала.
- События мыши не маршрутизируются по указателю: идут по z, как клавиши.
- Раскладка — только стек панелей снизу, Fullscreen и центрированные Overlay; боковых панелей и вложенности нет.
- Каждый кадр перерисовывает все элементы.
