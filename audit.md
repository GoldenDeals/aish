Код в хорошем состоянии: go vet, go test -race и staticcheck проходят чисто (у staticcheck одно замечание по стилю в cmd/aish/sessionrm.go:19). Серьёзные проблемы есть в трёх местах: обход политик, доверие к конфигу из чужого репозитория и одна ошибка, после которой сессия перестаёт работать. Безопасность и логику agent/llm/proxy проверяли два субагента. Пункт 1 по безопасности и последний пункт ниже я перепроверил сам, а случаи обхода политики субагент воспроизвёл в отдельной копии репозитория. Остальное я по коду не перепроверял.

Безопасность (главное)

Политику легко обойти, потому что internal/policy/commands.go разбирает только argv простых команд, $() и bash -c. Все эти команды проходят как allow:
eval 'rm -rf ~'
x=rm; $x -rf ~
echo sudo ls | bash
bash <<< '…'
source <(…)
env -S '…'
функции и алиасы. Они к тому же остаются в живом shell между вызовами.

Простое исправление: давать deny или ask, если имя программы содержит $, а также для eval, source/. и для bash или sh, читающего stdin.

Редиректы не проверяются. Stmt.Redirs нигде не читается, поэтому echo x > ~/.bashrc и cat > /etc/x разрешены. Правила write_outside_home и Cedar write действуют только на write_file и edit_file.
Чужой репозиторий может выполнить код и ослабить политику (internal/config/project.go:85-97). Файл .aish.toml в склонированном репо задаёт hooks_dir, и хуки user-prompt запустятся без запроса доверия. Ещё он может задать policy_dir: одна строка permit(principal,action,resource); в нём разрешает всё. Для deny и ask это уже сделано правильно, через stricter. Для каталогов нужен механизм доверия, как direnv allow, или их лучше вообще не брать из проекта.
Через висячий symlink можно писать за пределы home (policy.go:107-123 вместе с builtin.go:278-291). Ссылка ~/link -> /outside/new проходит проверку, а os.WriteFile идёт по ссылке и создаёт файл снаружи.
RPC resume не проверяет ID (proxy/resume.go:180,200). Через ../ можно выйти из sessions_dir. Кроме того, ID без кавычек попадает в export AISH_SESSION=<id> внутри скрипта, который выполняет shell. Так фоновый процесс от того же пользователя может выполнить команду в обход политики.
Помельче: write_file и edit_file пишут не атомарно (не через temp-файл и rename), ~ в путях не раскрывается. В examples/policy/default.cedar пропускаются rm --recursive --force и git push origin +main.

Корректность

Один пустой ответ Anthropic ломает сессию (internal/llm/anthropic.go:142). Raw сохраняется даже при пустом content, а при повторной отправке messages() берёт его как есть, минуя заглушку "(no response)". Это случается после refusal или пустого end_turn. Дальше каждый запрос получает 400, и не помогает даже compaction. Исправление: не сохранять Raw, если msg.Content пуст.
MCP по HTTP не переподключается после 404 (mcp/client.go:388): alive() всегда возвращает true.
Таймаут MCP-вызова не срабатывает, пока запись в stdin заблокирована (mcp/client.go:194-218). Сервер завис, аргументы больше 64 KB — и запись блокируется, держа мьютекс, так что этот сервер виснет целиком.
Ctrl+C может потеряться (proxy/agent.go:38-44), если запрос стоит в очереди за предыдущим.

Чего не хватает

Своих повторов при overloaded/5xx посреди стрима нет: ход падает, а уже полученный текст пропадает.
Ошибка «prompt too long» не обрабатывается, хотя на неё естественно отвечать автоматическим compact.
Stop reasons refusal и pause_turn не обрабатываются.
Точка кэширования одна (anthropic.go:300-306). После хода с большим количеством параллельных tool calls кэш промахивается.
Отменённый MCP-вызов не отправляет серверу notifications/cancelled.
